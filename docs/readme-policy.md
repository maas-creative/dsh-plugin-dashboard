# 名称とREADMEの編集方針

製品名は **Project Dashboard** とする。既存UI・Webアプリの名称と一致させ、成果プロジェクトを横断して管理する用途を伝える。独自の略語や別ブランドを追加しない。

リポジトリ名とパッケージ名 `dsh-plugin-dashboard` は既存のリンク・導入・ホスト参照との互換性のため維持する。製品全体はUI・サーバー・DSHプラグインを含むことをREADMEで説明する。

READMEは利用者が用途、実画面、導入、最初の操作、Scrumとの関係を順に理解できる構成にする。プロジェクトの完成形、タスクの出力・依存関係、締切と提出の区別を具体的に書く。

API、読取スコープ、カスタムホスト、OAuthアダプターの設定はruntime-reference.mdへ、公開作業と監査はpublication-guide.mdへ分離する。

試験件数、進捗報告、会話上の命名経緯、内部の保存パス、利用者の履歴、秘密情報はREADMEに書かない。未実証の安定性や他製品との完全互換、ネットワーク越しの無条件な安全性を保証しない。サンプル画面を実作業の結果として示さない。

OMOのREADMEからは利用者に向けた説明の順序を参考にし、宣伝文・推薦文・ブランドを転載しない。Scrumと同じ編集方針を用いるが、製品の業務管理とScrumの実行管理を混同しない。
